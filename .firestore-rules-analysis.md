# Firestore rules analysis (untracked)

Prototype rules for Synapse admin/superadmin. Not a security audit.

## Client queries

- `users` collection get/list (staff); owner `get` own doc
- `roles` collection get/list (staff)
- `tickets` where `uid == auth.uid` (owner); collection orderBy `createdAt` desc (staff)
- `tickets/{id}/messages` orderBy `createdAt`
- `moderation` orderBy `createdAt` desc (staff)
- `adminAudit` orderBy `createdAt` desc (superadmin)
- `publishedThemes` get/list (signed-in)

## Collections

See `firestore.rules` assumed data model. Roles never live on `users` documents. Superadmin is verified email only. Admin is `roles/{uid}` with `role == 'admin'` written only by superadmin.
